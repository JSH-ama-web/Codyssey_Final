## 2. 브랜치 전략 (GitHub Flow)

| 브랜치 | 용도 | 예시 |
|---|---|---|
| `main` | 배포 브랜치. 직접 push 하지 않고 PR로만 병합 | |
| `feat/*` | 기능 추가 | `feat/codyssey-gateway` |
| `fix/*` | 버그 수정 | `fix/sieve-order-validation` |
| `refactor/*` | 동작 변화 없는 구조 개선 | `refactor/ruff-format` |
| `docs/*` | 문서 | `docs/user-test-results` |

흐름: 브랜치 생성 → 커밋 → push → PR 작성(템플릿 사용) → CI 통과 → Vercel Preview 확인 → `main` 병합 → Production 자동 배포.

## 3. 커밋 메시지 규칙

`<타입>: <요약>` 형식, 타입은 `feat`, `fix`, `refactor`, `docs`, `test`, `chore`, `ci`.

예) `feat: 코디세이 AI Gateway 연동`, `refactor: ruff format 적용`, `docs: 사용자 테스트 T01~T05 결과 기록`

## 4. 코드 스타일

- 설정: `ruff.toml` (줄 길이 120, 작은따옴표, import 정렬, pyflakes·bugbear·pyupgrade 규칙)
- 로컬 검사: `ruff format app api tests && ruff check app api tests`
- 커밋 전 자동 검사(선택): `pip install pre-commit && pre-commit install`
- CI: 모든 push·PR에서 `ruff format --check`, `ruff check`, `pytest` 실행 → 실패 시 병합하지 않음
